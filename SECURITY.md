# Security policy

This policy applies to each repository of the `gsuquet` account that has no `SECURITY.md` of its own.

## Report a vulnerability

Do not open a public issue, a pull request or a discussion about a vulnerability.

1. Use GitHub private vulnerability reporting, in the Security tab of the repository, if it is on. The tab can have the name "Security and quality". Select **Report a vulnerability**, then fill in the form ([GitHub: privately reporting a security vulnerability](https://docs.github.com/en/code-security/how-tos/report-and-fix-vulnerabilities/report-a-vulnerability/privately-reporting-a-security-vulnerability)).
2. If the Security tab has no **Report a vulnerability** button, send an email to <contact@gsuquet.com>. Do the same if you have no GitHub account. For example, the button is not there when private vulnerability reporting is off for the repository.

## What to include

- The name of the repository, and the branch or the commit.
- A summary of the vulnerability and its possible effect.
- The steps to reproduce it, or a proof of concept.
- A fix or a mitigation, if you know one.

## What happens next

You get an answer to your report. The vulnerability gets a fix in private. After the fix, a security advisory can tell the details, with credit to you if you agree.

The repositories are personal projects. They have no support contract and no fixed response time.
